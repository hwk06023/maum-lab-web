# 배포 및 도메인 메모

## 현재 상태

원격 저장소 생성, 배포 서비스 생성, DNS 레코드 추가, TLS 인증서 발급은 이 전달물에서 실행하지 않았다. 제안 주소는 `maum.hyunwoo.ai`다. `hyunwoo.ai`의 실제 DNS 관리 업체·기존 레코드·사용 권한을 확인하지 않았다.

## 지속 실행 Node 서버

```sh
npm run check
npm test
APP_ORIGIN=https://maum.hyunwoo.ai HOST=127.0.0.1 PORT=3000 npm start
```

실행 프로세스를 유지할 관리자와 HTTPS 종단 프록시가 필요하다. 앱 포트는 공개 인터넷에 직접 노출하지 않는 구성을 우선 검토한다. 실제 서버의 운영 방식에 맞춰 프로세스 관리·상태 확인·보안 설정을 적용한다.

`APP_ORIGIN`은 브라우저가 보는 정확한 출처(스킴+호스트+필요시 포트)이며 끝에 `/`를 붙이지 않는다. 앱은 이 값으로 쓰기 요청의 Origin을 확인하므로 `http://localhost:3000`과 `http://127.0.0.1:3000`도 다른 출처다. 배포 도메인과 일치시켜야 한다.

## Docker 예시

```sh
docker build -t maum-lab:0.1.0 .
docker run --rm -p 127.0.0.1:3000:3000 \
  -e APP_ORIGIN=https://maum.hyunwoo.ai \
  -e LLM_MODE=demo \
  maum-lab:0.1.0
```

Docker 이미지는 이 작업 환경에서 실제 빌드하지 않았다. 베이스 이미지 취약점, 태그/다이제스트 고정, 배포 계정 권한은 운영 전에 검토한다. 실제 키는 이미지에 복사하지 않고 운영 환경의 비밀 관리 수단을 사용한다.

## DNS 계획

`hyunwoo.ai`의 DNS를 관리할 수 있다면, 새 상위 도메인을 구매하는 대신 `maum` 호스트 레코드를 만들 수 있다.

| 배포 형태 | 이름 | 레코드 | 값 |
|---|---|---|---|
| 고정 IPv4 서버 | `maum` | A | 실제 배포 서버 IPv4 |
| 고정 IPv6 서버 | `maum` | AAAA | 실제 배포 서버 IPv6 |
| 호스트명을 제공하는 플랫폼 | `maum` | CNAME | 해당 플랫폼이 안내하는 호스트명 |

위 표는 대안이다. 하나의 이름에 충돌하는 A/AAAA와 CNAME을 동시에 만들지 않는다. `hyunwoo.ai`의 메일·기존 웹 서비스·다른 서브도메인은 수정하지 않는다. 값은 서버/플랫폼이 확정된 후 그 실제 안내를 사용하며 임의의 IP나 CNAME을 지정하지 않는다. DNS만 연결한다고 HTTPS나 앱이 자동으로 동작하는 것은 아니다.

Cloudflare의 서브도메인 DNS 공식 안내: https://developers.cloudflare.com/dns/manage-dns-records/how-to/create-subdomain/

## 함수형 서버리스 환경으로 옮길 때

현재 세션, 중복 요청 캐시, 속도 제한, LLM 예산은 한 프로세스의 메모리다. 함수형 서버리스나 여러 인스턴스에서는 공유되지 않는다. 단순히 Vercel에 import하는 방식으로 운영할 수 있는 버전이 아니다.

그 환경이 필요하다면 세션의 외부 저장소(TTL 포함), 분산 rate limiter·예산, 원자적 버전 갱신, 공인 인증과 권한, 삭제 정책을 도입한 뒤 핸들러를 플랫폼에 맞게 나눠야 한다.

## 공개 파일럿 전 확인

기관의 실제 승인 범위, 콘텐츠 전문가 검토, 개인정보 입력 방지·전송 고지, 공급자 보관 설정, 보안·접근성 평가를 운영 담당자와 확인한다. 특정 기관의 법적·기술적 요건을 충족했다는 확인서는 아니다.

접근 코드는 소규모 파일럿용 임시 수단이다. 사용자별 인증과 권한을 대체하지 않는다. 공개 서비스에서는 프록시/WAF의 제한과 별도 인증을 적용하고 공급자 계정의 비용 한도를 설정한다. 프로세스 재시작으로 로컬 호출 한도가 초기화될 수 있다.
